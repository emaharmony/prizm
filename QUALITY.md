## Known Limitations
- Prizm is in **public preview**: source-available, local-first, and **not production-ready**. See [Stability Matrix](./docs/reference/stability-matrix.md) and [Public Preview Checklist](./docs/operations/PUBLIC_PREVIEW_CHECKLIST.md).
- Free Mode (owner-authorized mutation mode) grants a single configured Discord user account bypass of the approval-gate workflow for file, git, and shell mutations. File and directory writes still pass through independent workspace/write-root path containment at the tool layer even when auto-approved. The shell tool's working directory is **not** path-contained — only a small hard blocklist and the configured command-pattern tier restrict it. See [Safety Model](./docs/concepts/SAFETY.md) for the full breakdown.
- The `project.default_branch` config field is enforced by `GitCommitTool`/`GitPushTool` (`internal/tool/git.go`): those tools refuse to commit/push while the repo's current branch (or, for push, an explicitly targeted branch) equals the configured protected branch (default `"main"`), unconditionally — including under Free Mode. This is a single global value resolved from the default project (`Config.ProtectedBranch()`), not per-project; in multi-project deployments with differing `default_branch` values, only the default project's branch name is protected across every repo any git tool touches. See [Safety Model](./docs/concepts/SAFETY.md#free-mode-owner-authorized-mutation-mode).
- SDK Python tests (`sdk/tests/`) are not wired into any CI workflow; they were verified manually for this report in an isolated venv.
- External integrations (OpenAI, Anthropic, Gemini, Ollama, Discord, Codex CLI, Claude CLI, MCP servers, Firecrawl) are only as reliable as the third-party service and are not covered by Prizm's own test suite beyond mocked/contract-level tests.
