# V55 — Config Setup: Wizard + OpenClaw Import

**Status:** Source-current (complete)
**Last Updated:** 2026-07-01

## Goal

Make Prizm configuration **simple to start**. Two entry points, both under the
existing `prizm config` command:

- **`prizm config wizard`** — an interactive setup that asks a handful of
  questions (instance, workspace, provider, model, remembrance) and writes a
  ready-to-run `prizm.yaml`.
- **`prizm config import <openclaw.json>`** — convert an OpenClaw JSON model
  catalog into a Prizm `prizm.yaml`, one agent per provider.

Before this, the only way to get a `prizm.yaml` was to hand-author it against the
full `orchestrator.Config` struct, or run `prizm config` to validate one you'd
already written. There was no scaffolding path and no OpenClaw → Prizm bridge for
config (OpenClaw import existed only as an in-memory provider registry for
`prizm run --from-config`, not as a persisted Prizm config).

## Design

Key insight: **`LoadConfigFromBytes` overlays YAML onto `DefaultConfig()`**. So
the generated file only needs to carry what the user actually chose — everything
else fills in from defaults on load. Both commands therefore emit a **minimal,
tidy YAML** rather than dumping every default field.

### Curated export view (`cmd/prizm-cli/cmd_config_setup.go`)

- **`exportConfig`** — a small `omitempty` struct (`prizm`, `agents[]`,
  `remembrance`) that marshals to clean YAML. It is intentionally *not* the full
  `orchestrator.Config`; it's the write-view.
- **`marshalExport`** — `yaml.Marshal` + a two-line header comment.
- **`validateExport`** — runs the generated bytes back through
  `orchestrator.LoadConfigFromBytes` (the same validation `prizm serve` uses), so
  a config is never written unless it actually loads and validates.
- **`writeConfigOutput`** — writes to `--out` or stdout; refuses to clobber an
  existing file without `--force`.

### OpenClaw import (pure `openClawToExport`)

Reuses the existing `internal/config.OpenClawConfig` JSON structs (a
`models.providers` map). For each provider (sorted for deterministic output) with
≥1 model, it emits one agent: `id` = sanitized provider name, `provider` =
provider `api` (falling back to the map key), `model` = the provider's first
model, `context: [soul, user]`. The first agent is marked `primary`. Providers
with no models are skipped; an all-empty catalog is an error.
`prizm config import` with no path falls back to `FindOpenClawConfig("")` (the
default `~/.openclaw` location).

### Wizard (pure `wizardBuild` + thin I/O shell)

`runConfigWizard` collects answers over `bufio.Stdin` (each prompt shows a
`[default]`, blank/EOF accepts it), then calls the pure `wizardBuild(answers)`.
`--from-openclaw <file>` seeds the agent list from `openClawToExport` and skips the
provider/model questions. A seeded agent list with no primary gets its first entry
promoted. `sanitizeAgentID` maps arbitrary provider names to the agent-ID charset
(`[a-z0-9-]`, non-numeric start).

Both commands are dispatched as positional subcommands inside `executeConfig`
(`import`, `wizard`/`init`); bare `prizm config` still validates+summarizes.

## Why this shape

- **Pure core, thin shell** — `openClawToExport` and `wizardBuild` are pure
  functions returning `*exportConfig`, unit-tested without stdin or the
  filesystem; the interactive/file code is a thin wrapper (same pattern as the
  rest of the CLI: pure render/marshal + thin exec).
- **No new validation surface** — the generated config is proven by loading it
  through the real loader, not a parallel checker.
- **No core change** — no change to `orchestrator.Config`; reuses the existing
  OpenClaw structs and the default-overlay loader.

## Tests (`cmd/prizm-cli/cmd_config_setup_test.go`)

`openClawToExport` (skip-empty, sorted order, primary flag, first-model,
provider fallback), empty/invalid-JSON errors, `wizardBuild` single-agent and
seeded-primary promotion, `sanitizeAgentID` cases, and — the key guarantee —
`TestGeneratedConfigValidates` / the wizard test load the emitted YAML through
`orchestrator.LoadConfigFromBytes` to prove it's a valid, runnable config. Suite
stays green (71 packages); vet clean. Verified end-to-end with the built binary:
import to stdout/file, wizard via piped answers, `--from-openclaw` seeding, and
the overwrite guard.
