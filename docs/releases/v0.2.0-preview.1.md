# Prizm v0.2.0-preview.1 Release Notes

**Status: release candidate — not tagged.** These notes describe the state
of `main` at commit `9a21215d114dd65caa539e9b381539708a6dbaa5`, prepared for
review before the owner decides to tag.

## What Prizm Is

Prizm is a Go event-native AI agent runtime. Agents communicate over an
embedded NATS event bus; tool use is policy-gated and (by default)
approval-gated; every mutation passes through the same
approve → execute → validate → persist pipeline regardless of which model
proposed it. The runtime — not the model — owns lifecycle, policy,
approvals, budgets, context, validation, and persistence.

## Why This Release Matters

Since `v0.1.0`, Prizm gained a live API-backed dashboard, token-usage
visibility, and — the largest single change — **Free Mode**: an explicit,
narrowly-scoped exception to the approval-gate model for one trusted
operator working interactively over Discord. This release also closes a
significant chunk of technical debt: 163 broken documentation links from an
earlier `docs/` reorganization, unpinned CI actions, and several stale
quality metrics are all fixed as part of this pass.

## Main Capabilities

- Policy-gated, approval-gated tool execution (read/write/git/shell) with a
  deterministic policy engine — the model never grants its own permissions.
- The verified gated dev loop (`PROBE → RESEARCH → PLAN → FEEDBACK_PRE →
  EXECUTION → FEEDBACK_POST → REPORT`) with objective build/test
  verification before a phase can complete.
- Multi-agent delegation and bounded, worktree-isolated sub-agents.
- A same-origin dashboard (served by `prizm serve`) with a run browser,
  agent graph, visual workflow editor, token-usage graph, and a
  config/workspace editor.
- Optional, disabled-by-default integrations: Remembrance (external
  memory), MCP tool servers, Discord, and a cross-Prizm bridge.

## Important Changes Since v0.1.0

- **Dashboard redesign** — live API-backed overview replacing the previous
  static one.
- **Token-usage tracking** — session-to-lifetime usage graph plus a
  workspace/config file editor, both in the dashboard.
- **Free Mode (V60)** — a shell tool with a tiered command allowlist and a
  hard safety blocklist, plus a per-channel `mode: free` config option
  that, only for one configured Discord user, auto-approves mutations
  instead of gating them on approval. See **Safety Model** below — this is
  the single most consequential change in this release and needs to be
  understood before enabling it.
- **Discord interactive approval buttons** — Approve / Request changes /
  Reject, replacing text-command approvals.
- **`docs/` reorganized** into topic subdirectories
  (`getting-started/`, `operations/`, `architecture/`, `concepts/`,
  `history/`, `reference/`, `dashboard/`, `quality/`); every inbound link
  across the repo was updated to match.
- **CI hardening** — all three GitHub Actions workflows now pin third-party
  actions to immutable commit SHAs (previously only two of three did).
- **Coverage gates, release-build smoke tests, and SDK contract tests**
  added to the local verification toolchain.

## Safety Model

Prizm's default posture is unchanged: the policy engine decides tool
permission deterministically, and file mutations require an approval gate
resolved by a human or configured reviewer — never by the acting model.

**Free Mode is the one documented exception**, and it is scoped tightly:
off by default, requires both a channel configured `mode: free` *and* the
message sender matching a single configured Discord user ID, cannot be
triggered by any other user or remotely, and resets after each message. File
and directory writes are still independently path-contained to the
workspace/write roots even when auto-approved. The shell tool's working
directory is **not** similarly contained — only a hard blocklist and the
channel's configured command tier restrict it. Read the full breakdown
before enabling Free Mode on anything but a personal, single-owner
deployment: [Safety Model → Free Mode](../concepts/SAFETY.md#free-mode-owner-authorized-mutation-mode).

Separately: `project.default_branch` is enforced by `GitCommitTool` and
`GitPushTool` — they refuse to commit or push while the repo's current
branch (or, for push, an explicitly targeted branch) matches it, always
(including under Free Mode). This is a single global value from the default
project, not per-project — see [Safety Model → Free Mode](../concepts/SAFETY.md#free-mode-owner-authorized-mutation-mode)
for the exact scope.

## Public-Preview Warning

Prizm is **source-available**, **local-first**, in **public preview**, and
**not production-ready**. Several features are explicitly experimental (see
the [Stability Matrix](../reference/stability-matrix.md)). Do not use it for
unattended high-risk automation, live trading, or sensitive production
workflows without independent review and hardening.

## Supported Setup

- **Go 1.26+** to build; no external database or broker required (embedded
  NATS JetStream + SQLite).
- **Linux** is the only platform with a full CI-verified test suite.
  **Windows** CI runs a build plus a basic subset of tests
  (`internal/safety`, `internal/config`, `internal/run`) plus a CLI smoke
  test — not the full suite. **macOS** is build-verified via cross-compile
  only; there is no macOS CI job.
- Optional: Python 3.11+ for the Remembrance memory service, Ollama for
  local models, Claude/Codex CLI for subscription-based providers, `gh` CLI
  for autopatch PR mode.

## Five-Minute Demo

```bash
go test ./...
go run ./cmd/prizm-cli workflow run demo.echo_tool
go run ./cmd/prizm-cli workflow status <run_id>
```

No API key, model, or external service required — inspect
`runs/<run_id>/events.jsonl` and `summary.json` afterward.

## Known Limitations

- Coverage gates (`scripts/coverage-gate.sh`) run and pass locally (55.4%
  aggregate, all critical packages ≥80%) but are not wired into any CI
  workflow yet — a manual/pre-release check, not a continuous one.
- The shell tool's working directory is not path-contained.
- SDK Python tests are not wired into CI (verified manually for this
  release).
- No macOS test execution exists; macOS support is build-verified only.
- No dashboard screenshots or demo video exist yet.

See [QUALITY.md](../../QUALITY.md) for the full verified-metrics report and
the [v0.2.0-preview.1 checklist](./v0.2.0-preview.1-checklist.md) for exactly
what is and isn't verified.

## Upgrade Notes

There is no prior tagged release to upgrade from (`v0.1.0` was never tagged
— it exists only as a `CHANGELOG.md` entry and `VERSION` value). If you have
a checkout from before this release: `prizm.yaml` gains new optional
`shell` and `channel_roles[].mode`/`channel_roles[].shell_policy` fields
(all default to disabled/gated); no existing config needs to change unless
you intend to opt into Free Mode.
